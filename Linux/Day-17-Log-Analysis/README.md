Day 17 — Linux Log Analysis with grep, sed and awk
Objective

Practice manual Linux log triage using grep, sed, and awk against real authentication events from a Kali Linux system.

The goal was to understand how security analysts can search, clean, and extract useful information from raw logs before using a SIEM.

Environment
OS: Kali Linux
Log system: systemd journal
Log access tool: journalctl
Analysis tools: grep, sed, awk
Why This Matters

Command-line log analysis is a useful skill for SOC analysts. Before searching events in a SIEM, analysts may need to quickly inspect raw logs, filter relevant events, remove unnecessary information, and extract specific fields.

Step 1 — Identify the Log Source

The system did not have /var/log/auth.log, so the systemd journal was used instead.

sudo journalctl

This provides access to authentication and other system events recorded by the journal.

Step 2 — grep: Find Authentication Failures
sudo journalctl | grep -Ei "authentication failure" | head -10
What it does
journalctl reads the system journal.
grep searches for matching text.
-E enables extended pattern matching.
-i makes the search case-insensitive.
"authentication failure" is the search pattern.
head -10 limits the results to the first 10 matches.
Result

Real authentication failure events were found, including events generated by lightdm and sudo.

Step 3 — sed: Clean the Log Output
sudo journalctl | grep -Ei "authentication failure" | head -10 | sed 's/pam_unix([^)]*): //'
What it does

sed was used to remove the pam_unix(...) portion of each matching log entry.

This reduced unnecessary technical information and made the authentication failure details easier to read.

Result

The same authentication events were displayed with the unnecessary pam_unix(...) section removed.

Step 4 — awk: Extract a Specific Field
sudo journalctl | grep -Ei "authentication failure" | head -10 | awk '{for(i=1;i<=NF;i++) if($i ~ /^user=/) print $i}'
What it does

awk examines each field in the log entry and identifies fields beginning with user=.

This demonstrates how awk can extract specific information from structured or semi-structured log data.

Result

The available user= fields were extracted from the authentication events.

Important Observation

The authentication events available on this Kali system did not contain a remote source IP address.

SSH logs were also checked for failed remote login attempts, but no failed SSH authentication events were currently available.

Because the required IP information was not present in the actual logs, no IP address was fabricated or extracted from unrelated fields.

This is an important part of real-world log analysis: work with the evidence that actually exists in the logs.

SOC Relevance

This exercise demonstrates a basic manual log-triage workflow:

Search → Filter → Clean → Extract → Investigate

These techniques can be useful when reviewing raw authentication logs, troubleshooting security events, or preparing data for deeper analysis in a SIEM.

Key Takeaways
Linux systems may store authentication events through different logging mechanisms.
grep can quickly locate relevant security events.
sed can remove unnecessary information from raw log output.
awk can extract specific fields from log entries.
Analysts should not assume that every authentication event contains a source IP.
Log analysis should be based on the actual evidence available in the system.
